# Contributing

Thanks for helping with Copilot PPTX Review Canvas. Bug reports, fixes, translations and ideas are all welcome.

## Prerequisites

- Windows 10 or 11 (the renderer drives desktop PowerPoint through COM).
- Node.js 22 or later. There are no runtime or development dependencies, so there is no `npm install` step.
- Desktop Microsoft PowerPoint, only for the smoke test and for screenshots. The unit tests use a fake renderer.
- Python with [uv](https://docs.astral.sh/uv/), only to regenerate the sample deck.

## Run the tests

```powershell
npm test
```

This runs every `*.test.mjs` file in [`com.github.copilot/extensions/pptx-review-canvas/test/`](./com.github.copilot/extensions/pptx-review-canvas/test). To check the real renderer against your PowerPoint:

```powershell
npm run smoke
```

## Try your change

Add your clone as a local marketplace and install from it. A local marketplace is loaded live, so edits take effect in the next session without reinstalling:

```powershell
copilot plugin marketplace add C:\path\to\copilot-pptx-review-canvas
copilot plugin install copilot-pptx-review-canvas@copilot-pptx-review-canvas
```

Uninstall any other copy of the plugin first, so that the canvas is not registered twice. After changing `assets/` or `lib/`, start a new session; the page and the server read their files when the viewer starts.

## Where things live

[docs/architecture.md](./docs/architecture.md) describes the modules, the HTTP API and the data the extension keeps. The extension itself is in `com.github.copilot/extensions/pptx-review-canvas/`; the plugin manifest is `plugin.json` at the repository root.

## Guidelines

- **No dependencies.** The extension uses Node built-ins and plain browser ES modules, with no build step. Please keep it that way.
- **Translate every visible string.** Text that a person or the agent reads goes into the catalogs, never inline: `lib/locales/en.mjs` and `lib/locales/ja.mjs` for the server, and `assets/locales/en.js` and `assets/locales/ja.js` for the browser UI. Both languages must have the same keys and placeholders; `test/i18n.test.mjs` and `test/ui-i18n.test.mjs` check this. Write the English first. If you cannot write Japanese, leave the Japanese entry as a best-effort translation and say so in the pull request. To propose another language, open an issue first.
- **Keep the README short.** It is the front page: what the project is, install, quick start and links. Put details in `docs/`, and mirror each page in Japanese under `docs/ja/` with the same file name (the architecture page is English only). Say each fact in one place and link to it. `test/package.test.mjs` checks every relative link and heading anchor in the Markdown files.
- **Mind the page policy.** The page is served with `style-src 'self'`, so do not add `style=` attributes or inline `<style>` blocks. Use classes or the CSSOM.
- **Be careful with the `.pptx` file.** Reordering and deleting slides rewrite the file (`lib/pptx-zip.mjs`, `lib/pptx-reorder.mjs`, `lib/pptx-delete.mjs`). When you change them, add a test, run `npm run smoke`, and open a rewritten deck in PowerPoint to confirm that it opens without a repair prompt.
- **Keep paths short.** VS Code copies an installed plugin under `%APPDATA%\Code - Insiders\agentPlugins\`, and the folder name of the copy contains the marketplace and plugin names. For a user name of 8 characters the prefix is about 180 characters, and every extra character of the user name adds two. A copy fails on a PC where Windows long paths are disabled (260 characters), so no path in the repository may be longer than 72 characters; `test/package.test.mjs` checks this. If a new file would be longer, shorten its name rather than raise the limit.
- **Keep the sample deck neutral.** `samples/q3-review.pptx` is generated by `scripts/make_sample_deck.py`; change the script and regenerate rather than editing the file. Screenshots must show only this deck.
- **Edit the diagram's SVG, not its PNG.** `docs/images/concept.png` and `ja-concept.png` are rendered from `docs/images/src/*.svg` in the colors of the sample deck. Render with Edge: `msedge --headless=new --hide-scrollbars --force-device-scale-factor=2 --window-size=1135,529 --screenshot=<png> <svg as a file URL>`. The window size is the `width` and `height` of the SVG, which crops the picture to 24 px of white around it; change them together with the `viewBox`.

## Commits and pull requests

- Use [Conventional Commits](https://www.conventionalcommits.org/), for example `fix(reorder): keep sections when moving the first slide`.
- Describe the change, how you tested it, and your Windows and PowerPoint versions for anything that touches rendering or the file rewrite. Add a before and after screenshot for UI changes.
- Keep a pull request to one topic.

## Releasing

The plugin version and the git tag are the same number.

1. Set the same SemVer `version` in `plugin.json`, `package.json` and `.github/plugin/marketplace.json` (twice: `metadata.version` and the plugin entry). `npm test` fails when they differ.
2. Merge to `main`, then tag the merge commit `v<version>` (for example `v1.1.0`) and push the tag. The `release-check` workflow fails the run when the tag and `plugin.json` disagree.
3. Do not move a published tag; release a new version instead.

## Reporting a bug

Open an issue with the steps to reproduce, what you expected and what happened, your Windows and PowerPoint versions, and which Copilot client you use (VS Code, Copilot CLI or the Copilot app). The extension writes its logs to the session timeline, and its data is kept under `~/.copilot/extension-data/pptx-review-canvas/`; please do not attach decks that contain confidential information.

For security problems, follow [SECURITY.md](./SECURITY.md) instead of opening a public issue.

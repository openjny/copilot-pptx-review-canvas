# 仕組み

[English](../how-it-works.md)

## 書き込みから修正まで

```mermaid
flowchart LR
  A[スライドに書き込み、コメントする] --> B[「レビューを提出」を押す、またはチャットで指示を送る]
  B --> C[エージェントが書き込み、コメント、番号付きの画像を読む]
  C --> D[エージェントが資料を直して保存する]
  D --> E[キャンバスがファイルを描き直す]
  E --> A
```

- 書き込みはスライドに対する割合（0 から 1）で保存するため、ウィンドウの大きさが変わっても位置はずれません。
- 「レビューを提出」は、キャンバスを開いたセッションのエージェントにメッセージを送ります。どの資料のどのスライドに新しい指摘があるかを伝え、`get_annotations` ですべて読むよう依頼します。ボタンを押すとすぐに送られ、確認の手順はありません。エージェントが作業中のときは、順番を待ちます。提出できるのは、エージェントがまだ読んでいない指摘だけで、同じ指摘は 1 回だけです。続けて書き込むかコメントすると、ボタンがまた押せます。
- エージェントからも書き戻せます。`add_comment` は、位置やスライド全体にエージェント自身のコメントを付けます（「ここを直しましたが、イメージに合いますか」「この主張は根拠が薄いので、重点的に見てください」など）。`reply_to_comment` は、スレッドに返信します。これらは「エージェント」と表示され、青緑色で描かれます。あなたは同じスレッドに返信し、片付いたら解決済みにします。あなたのコメントと返信は、エージェントがまだ読んでいない指摘になります。エージェント自身のコメントと、スレッドの解決は、なりません。
- エージェントが新しい版を保存すると、見た目が変わっていないスライドの書き込みは残ります。変わったスライドの書き込みは退避され、古い指摘が新しい内容を指すことはありません。
- 代わりにチャットでエージェントに伝えるとき（たとえば「書き込みとコメントを反映して」）は、次のメッセージで、まだ読まれていない書き込みがあるスライドをキャンバスがエージェントに伝えます。
- キャンバスはスライドの内容を編集しません。編集はエージェントが、python-pptx、ビルドスクリプト、PowerPoint の自動操作など、それぞれの道具で行います。

## データとプライバシー

データはすべて `~/.copilot/extension-data/pptx-review-canvas/` に保存します。描画した画像、書き込み、コメント、新しいスライド、書き換え前のファイルのバックアップ、各資料で最後に見たスライド、設定が入ります。PC の外には出ません。テレメトリーもありません。

- ビューアは、開いているキャンバスのためだけに、ランダムなポートで `127.0.0.1` に立てる小さな Web サーバーです。ほかのホストやオリジンからの要求は拒否します。
- 資料は、マクロを無効にし、確認の画面も出さずに、PowerPoint で読み取り専用で開きます。
- .pptx を書き換えるのは、スライドを並べ替えるか削除するときだけです。書き換える前にバックアップを取ります。バックアップは、ファイルごとに最後の 1 つです。

## 制限事項

- Windows とデスクトップ版の PowerPoint のみ対応します。
- スライドは静止画として表示します。アニメーション、画面切り替え、動画、埋め込みメディアは再生されません。
- 別のアプリで開いている資料、.ppt のような旧形式、スケッチブックでは、並べ替えと削除はできません。理由は画面の上部に表示されます。
- 最後の 1 枚のスライドと、ほかのスライドからリンクされているスライドは削除できません。
- キャンバスは Copilot のクライアントのプレビュー機能のため、拡張機能の API が変わる可能性があります。

モジュール、HTTP API、保存するデータの詳細は、[アーキテクチャ](../architecture.md)（英語）を参照してください。
